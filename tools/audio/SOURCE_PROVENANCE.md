## Extracted engine
AAS2 reuses the same offline generation engine and pinned model used by the legacy project:
- Runtime: `sherpa-onnx 2.0.1`
- Model: Supertonic 3 INT8, model revision `supertonic3-int8-2026-05-11`
- Model archive SHA-256: `82fa96f91c4ef8abaae3a14a3f4153facf88bed821d1f7331cec2700f432c427`
- Voice style: `F1`, speaker ID 0, 8 inference steps, 2 CPU threads
- Encoding: OGG Opus, 48 kbps
- License notice: BigScience Open RAIL-M; model revision/license must be preserved with distribution.

## AAS2 adaptation
The legacy generator was adapted for the current product requirements:
- English-only output. Arabic helper, Arabic UI, and Arabic feedback generation from the old project are deliberately excluded.
- English sentence and single-word speed are both set to **0.70**. The legacy project used 0.90 for English sentences and 0.95 for isolated English words; the lower AAS2 target responds to the user's explicit feedback that 0.95 remained too fast.
- Each English activity receives separate local clips for prompt, every option, correct feedback, and incorrect encouragement.
- The generated paths are written into the activity record; the app does not need a network lookup or TTS runtime.
- Generated files are stored under `app/src/main/assets/speech/`; the manifest records language, speed, source activity/role, duration, byte length and SHA-256.
- The Android app contains only pre-generated audio and a manifest. Supertonic model weights and sherpa-onnx runtime remain in the temporary GitHub Actions environment and are not packaged.
- The app uses one cancellable local MediaPlayer controller. It stops the previous clip when a new clip is requested and stops playback when the child changes or submits an answer.

## Non-use of legacy Arabic audio
The legacy generator also supported Arabic helper text, Arabic UI and Arabic encouragement. Those parts are intentionally not carried into AAS2 because the current product decision is English audio only, including encouragement. No Arabic speech files are generated by the AAS2 pipeline.

## Verification boundary
A successful CI generation run proves that the generated files and manifest pass automated integrity checks. It does not prove perceived pronunciation quality, 70% subjective pacing, phoneme accuracy, or actual Android playback. Those require listening and real-device tests, including Airplane Mode.
